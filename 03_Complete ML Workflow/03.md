## 13\. Model Evaluation

**Definition\:** Model evaluation is the process of measuring how well a trained Machine Learning model performs on unseen data.

The evaluation metrics depend on the type of ML problem.

### A. Classification Metrics

| Metric | Meaning |
|--------|--------|
| Accuracy | Proportion of all predictions that are correct |
| Precision | Proportion of positive predictions that are correct |
| Recall | Proportion of actual positives correctly identified |
| F1-score | Harmonic mean of precision and recall |
| ROC-AUC | Measures how well a model ranks positive cases above negative cases |

**Important formulas\:**

$$
Accuracy=\frac{TP+TN}{TP+TN+FP+FN}
$$

$$
Precision=\frac{TP}{TP+FP}
$$

$$
Recall=\frac{TP}{TP+FN}
$$

$$
F1=2\cdot\frac{Precision\times Recall}{Precision+Recall}
$$

Where\:

- TP: True Positive
- TN: True Negative
- FP: False Positive
- FN: False Negative

**Python example\:**

```python
from sklearn.metrics import (
    accuracy_score,
    precision_score,
    recall_score,
    f1_score,
    classification_report
)

print("Accuracy:", accuracy_score(y_test, y_pred))
print("Precision:", precision_score(y_test, y_pred, zero_division=0))
print("Recall:", recall_score(y_test, y_pred, zero_division=0))
print("F1-score:", f1_score(y_test, y_pred, zero_division=0))

print(classification_report(y_test, y_pred, zero_division=0))
```

### B. Regression Metrics

| Metric | Meaning |
|--------|--------|
| MAE | Average absolute prediction error |
| MSE | Average squared prediction error |
| RMSE | Square root of MSE |
| R² Score | Measures performance relative to predicting the target mean |

$$
MAE=\frac{1}{n}\sum_{i=1}^{n}|y_i-\hat y_i|
$$

$$
MSE=\frac{1}{n}\sum_{i=1}^{n}(y_i-\hat y_i)^2
$$

$$
RMSE=\sqrt{MSE}
$$

**Python example\:**

```python
from sklearn.metrics import (
    mean_absolute_error,
    mean_squared_error,
    r2_score
)
import numpy as np

mae = mean_absolute_error(y_test, y_pred)
mse = mean_squared_error(y_test, y_pred)
rmse = np.sqrt(mse)
r2 = r2_score(y_test, y_pred)

print("MAE:", mae)
print("MSE:", mse)
print("RMSE:", rmse)
print("R2 Score:", r2)
```

**Important\:** Select metrics based on the business objective. For example, recall may be especially important when missing a high-risk loan applicant is costly.

## 14\. Hyperparameter Tuning

**Definition\:** Hyperparameter tuning is the process of finding suitable model settings that improve performance on validation data.

**Parameter vs. hyperparameter**

| Parameter | Hyperparameter |
|--------|--------|
| Learned during training | Specified before or during model fitting |
| Example: Regression coefficients | Example: Tree depth |
| Estimated from data | Selected using a tuning strategy |

**Common techniques\:**

- Grid Search
- Randomized Search
- Cross-validation
- Bayesian optimization

**Example using GridSearchCV\:**

```python
from sklearn.model_selection import GridSearchCV
from sklearn.ensemble import RandomForestClassifier

model = RandomForestClassifier(random_state=42)

param_grid = {
    "n_estimators": [100, 200],
    "max_depth": [5, 10, None],
    "min_samples_split": [2, 5]
}

grid_search = GridSearchCV(
    estimator=model,
    param_grid=param_grid,
    cv=5,
    scoring="f1",
    n_jobs=-1
)

grid_search.fit(X_train, y_train)

print("Best parameters:", grid_search.best_params_)
print("Best CV score:", grid_search.best_score_)

best_model = grid_search.best_estimator_
```

**Explanation\:**

- `n_estimators`\: Number of trees in the forest.
- `max_depth`\: Maximum depth of each tree.
- `min_samples_split`\: Minimum samples required to split a node.
- `cv=5`\: Uses five-fold cross-validation.
- `scoring="f1"`\: Selects settings using the F1-score.

**Important\:** Use training data for tuning, and reserve the test set for final evaluation. For time-series problems, use time-aware cross-validation.

## 15\. Final Model

**Definition\:** The final model is the selected model that meets the required performance and operational criteria.

**Steps\:**

1. Compare candidate models.
2. Review cross-validation results.
3. Check business requirements.
4. Choose suitable hyperparameters and decision thresholds.
5. Evaluate the selected model on the untouched test set.
6. Approve the model for deployment if it meets the acceptance criteria.

**Example\:**

| Model | Validation F1-score |
|--------|--------|
| Logistic Regression | 0.78 |
| Decision Tree | 0.81 |
| Random Forest | 0.87 |

In this example, Random Forest has the highest validation F1-score. It may be selected if it also meets other requirements, such as inference speed and interpretability.

```python
final_model = grid_search.best_estimator_
```

**Important\:** The highest score alone does not guarantee the best production model. Reliability, fairness, latency, cost, and maintainability also matter.

## 16\. Model Saving

**Definition\:** Model saving is the process of storing a trained model so that it can be loaded and used later without retraining.

A common Python approach is to use `joblib` for scikit-learn models.

```python
import joblib

joblib.dump(final_model, "loan_model.joblib")
```

Load the model later\:

```python
loaded_model = joblib.load("loan_model.joblib")

predictions = loaded_model.predict(X_test)
```

**Why save a model?**

- Reuse the trained model.
- Integrate it into applications.
- Avoid unnecessary retraining.
- Maintain a deployable model artifact.

**Production considerations\:**

- Save required preprocessing objects and feature definitions.
- Record the model version and training metadata.
- Use a consistent feature order and schema.
- Load artifacts only from trusted sources; serialized Python objects can execute malicious code.
- Keep the training and inference environments compatible.

## 17\. Deployment

**Definition\:** Deployment is the process of making a trained model available to users or other software systems.

**Common deployment approaches\:**

| Approach | Example |
|--------|--------|
| Web application | Streamlit |
| REST API | FastAPI or Flask |
| Cloud service | AWS, Azure, Google Cloud |
| Batch prediction | Scheduled predictions for thousands of records |
| Edge deployment | Running a model on a local device |

**Example: FastAPI prediction endpoint**

```python
from fastapi import FastAPI
from pydantic import BaseModel
import joblib
import pandas as pd

app = FastAPI()
model = joblib.load("loan_model.joblib")

class LoanApplication(BaseModel):
    age: int
    cibil_score: int
    annual_income: float

@app.post("/predict")
def predict(application: LoanApplication):
    data = pd.DataFrame([application.model_dump()])
    prediction = model.predict(data)[0]

    return {"prediction": int(prediction)}
```

**Important\:** This example assumes the model was trained using exactly these three features, in compatible formats, without additional preprocessing. Production deployments must validate inputs, handle errors, secure endpoints, and maintain preprocessing consistency.

## 18\. Monitoring

**Definition\:** Monitoring is the continuous process of checking whether a deployed model remains accurate, reliable, and useful as real-world data changes.

**What should be monitored?**

- **Prediction quality\:** Compare predictions with actual outcomes when labels become available.
- **Data drift\:** Detect changes in input feature distributions.
- **Concept drift\:** Detect changes in the relationship between inputs and the target.
- **System performance\:** Track latency, errors, availability, and resource usage.
- **Business metrics\:** Monitor default rates, fraud losses, or other relevant outcomes.
- **Fairness\:** Check for performance differences across relevant groups.

**Example\:** A loan model was trained using historical applicant data. Over time, income distributions and repayment behavior change. The model may become less reliable even though the application still runs correctly.

**Possible responses\:**

1. Investigate the source of the change.
2. Evaluate the model using newly available labeled data.
3. Retrain or recalibrate if justified.
4. Validate the updated model before deployment.
5. Keep versioning and rollback mechanisms available.

**Important\:** Data drift does not necessarily mean model performance has declined. Verify the impact using appropriate evaluation data.

**Industry practice\:** Machine Learning is an iterative workflow, not strictly a one-way sequence. Monitoring results can reveal data-quality problems, new business requirements, or the need to retrain a model.
